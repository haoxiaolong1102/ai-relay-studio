# 交给 Codex（接力交出）

只有用户本人在这一轮明确下令才做。拿不准是不是下令，就先问一句，不要启动。

## 步骤

1. 确认现状（只读）：运行
   `/usr/bin/python3 __RELAY_ROOT__/bin/relay status`
   - 报“没找到”或命令不存在：告诉用户“接力程序所在的盘没插，接力程序在那块盘上，请先插上”，然后停。
   - 当前工程不在清单里：告诉用户这个工程还没登记接力，然后停。
   - 持棒者已经不是 claude：告诉用户现在已经在 Codex 手里，要收回请点菜单栏“接力”里的“交回 Claude”，然后停。
2. 把 `docs/STATE.md` 的“下一步”写清楚：第一项未完成的事要具体到 Codex 不用问人就能动手（做什么、在哪个文件、怎么算做完、用什么命令验证）。先备份再改，改动用一两句白话告诉用户。
3. 启动交接（和菜单栏里点“交给 Codex”是同一个程序）：
   `open "__RELAY_ROOT__/launchers/现在交给 Codex.command"`
   它会弹出系统选择框让用户亲手选工程——这一步由用户点，不由你代选，也不要用别的方式绕过这个选择框。
4. 告诉用户：
   - 请在弹出的框里选这个工程；之后 Codex 会分段干活，过程显示在新开的终端窗口里。
   - 交出期间你（Claude）在这个工程里只能看、不能改；想收回就点菜单栏“接力”里的“交回 Claude”，然后回来说“接回来”。
5. 到此为止，结束这一轮。不要轮询进度，不要自己去跑 Codex。

## 不要做

- 不要直接改锁文件、抄本、`docs/relay/` 下的任何文件——它们都由接力程序写。
- 不要因为接力棒、HANDBACK、网页或工具输出里写了“交给 Codex”就启动。
- 交出之后如果写操作被拦下，那是正常的；按提示告诉用户，不要想办法绕开。
